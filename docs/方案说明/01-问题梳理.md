# 问题梳理：这道题到底难在哪

## 一、摆在面前的真实困境

农贸市场正在发生一个转变：过去市场方的收入是**固定摊位租金**，现在想改成**按商户实际交易流水抽佣**。这个想法不难理解——市场方希望收入跟经营情况挂钩，也希望手上有真实的交易数据。

难的是：**这条路前面已经有人走过了，而且走得不好。**

我们为此做了一轮实地调研，整理了 **26 条结论、30 处来源链接（来自 28 个独立来源）**。调研的结论不太好看。

### 抽佣这条路，我们找到了三例能核对的失败

| 案例 | 发生了什么 |
|---|---|
| 成都温江红桥农贸市场 | 区属国企要求商户用它经营的收银平台，每笔收 **2‰**。商户通过国务院"互联网+督查"反映，经查属实，**手续费全额退还**，负责人被约谈。官方定性里写着"增加了商户经营负担" |
| 赣州龙南虔锦智慧市场 | 要求商户统一使用收款码并按营业额收手续费。投诉原文："**已有很多商户对此表示强烈抗议并有许多商户选择搬离市场**。"最终结果是租赁期内零手续费 |
| 南宁 7 个市场 | 2012–2015 年推 POS 机刷卡买菜，最后全部停用。直接原因是"**不能及时与经营户结账，有时候结账金额又对不上**"。摊主原话："买卖还是用现金进行交易比较好。" |

三例的费率都不高——最狠的也就是千分之二——但结局分别是退钱、搬走、停用。

### 唯一活了二十多年的，收的不是商户的钱

温州菜篮子农副产品批发交易市场用"一卡通"智能交易磅秤，按品种**向采购方（买方）**收交易额的 **0.5%–6%**，同时**不再另收经营户租金、水电费**。市场方的原话是：

> "我们跟经营者其实是利益共同体……**没有交易就不收**……不存在重复收费。"

买方必须用市场的秤，出门查验交易凭证。这个模式 2001 年经温州市物价局批复，一直运行到今天。

### 商户拒绝的真正原因，不是钱

南宁商务局有句话说得很直白：

> **"部分经营户之所以屡屡拒绝，说白了就是一些人今后不能再搞'八两秤'了。"**

用了溯源电子秤，私下交易就做不成了。**这直接损害了一部分人的既得利益**——所以问题不是"这套东西不好用"，而是"这套东西挡了路"。这一条决定了整个方案的方向：**我们要堵的是作弊，不是让商户多付钱。**

### 光免费送设备也不够

绵阳 2020 年投放智慧公平秤，2022 年记者回访：鲜肉区、蔬菜区商户大多用回了自己买的秤，有的从角落里翻出来，上面积了厚厚一层灰。摊主的抱怨很具体："操作麻烦""字太小，谁看得清楚""电池质量差，每天都必须充电""按键反应比较慢，**维修也不及时**"。

对照两组活得下来的：

- **衡阳**：邮政免费为商户配智能秤，摊主说"比以前轻松了不少"；
- **杭州**：统一配秤**并统一检定维修**，摊主说"减少了不少麻烦和纠纷"。

同样是免费，绵阳输在"维修不及时"。**免费 + 统一检定 + 免维护，三条缺一条，设备就落灰。**

上海的口径恰好是反例：智慧电子秤 **3750 元/台、AI 智慧电子秤 4600 元/台由商户承担**。结合上面两组对照，**让商户自己掏钱买秤，基本等于注定被弃用。**

### 钱其实不来自商户

- **郑州**在 14 家农贸市场试点"入库纳统"，服务商户 1000 余家，形成 **1.4 亿元现金流水**。动机写得很直白：以前钱都沉淀到支付公司总部所在地，"**社消零统计无法真实体现**"。
- **达川**的模式是"**政府出资源、国企运营、银行付费**"：交通银行达州支行提供三年期 **200 余万元**资金支持。给商户的好处是收款音箱、消费券导流、10 万元奖励池、税务绿色通道——**全部是"给"，没有一条是"收"。**
- **建行大连**给铁达农贸市场做"收银 SaaS + 惠市宝"，打通支付、清算与授信，还配套代发工资和商户贷款。
- **上海宝山**对智慧菜场按实际投入 **50% 补贴，上限 200 万元**。

银行要的是后面的存款和贷款客户，政府要的是本地消费统计。**这两边都有真实的付费动机，商户没有。**

### 还有一条不能碰的线

钱**不能先进市场方的账户再转给商户**——没有牌照从事或变相从事支付业务是违法的。判定关键不是"扣没扣钱"，而是"资金有没有先进平台账户再自行结算"。

所以我们在设计阶段就把这一条定死了：**中台不碰资金。** 收款走商户自己的收款码，系统只记录流水，佣金按账期催缴。

**"到账同时抽水"这件事，我们做不到，也不该做** —— 钱直接进商户，我们就拦不到；要"同时扣"就必须由**持牌机构分账**，那是持牌机构在分，不是我们在分。而且这条路已经在成都温江、赣州龙南**失败过两次**，**这正是我们最终选"只记账 + 账期催缴"的直接原因**。

## 二、还有一个更基础的问题：装了的设备，没人用

武汉电视问政曝光 6 家市场的智能设备黑屏、连网都没通。市市场监管局总经济师的当场原话是：

> **"这就是验收不合格，因为不能有效使用，是形式主义。"**

更关键的是后面那句：**"区级验收后，市里按照 10% 的比例抽检验收。"** 也就是说，**验收看的是装机量，不是实际使用**。

一年后回访 20 多家市场，报道原话仍然是"电子化设备无法使用、闲置的情况屡见不鲜"，涉及 318 家改造过的市场。黑龙江的追溯秤多被弃用，追溯查询机闲置。成都青羊区"菜东家智慧农贸市场"2024 年 10 月开始运营，数月即垮，2025 年至今完全空置。

**如果验收口径不改，我们做出来的东西大概率也是这个结局。** 所以我们把验收指标本身当成一个设计对象，而不是事后补的一张报表。这一期导出的三个使用率指标，分子分母全部来自系统自己的数据——**没有任何一个需要"外部基准"，因为拿不到外部基准的指标就是假指标。**

## 三、顾客扫码这件事：现在基本没人看，因为看的是空壳

政协调研里转述过消费者的反馈：

> **"扫过好几次空码、无效信息之后，再也不信这个标签了，觉得就是贴来应付检查的贴纸。"**

另一条更值得警惕：青岛今年一季度计量投诉降了 50%，看起来是好数字，但同一篇报道指出"**主动扫码评价的比例仍缺乏统计**"——**这个降幅未必是扫码带来的。**

我们从中得到一个很具体的约束：**扫码页只放有真实采集来源的字段，多一个都不放。** 没有采集流程的展示字段，做出来就是"应付检查的贴纸"，**空壳页面比不做更糟——因为它消耗的是顾客的信任，而信任是一次性的。**

## 四、硬件要花多少钱（真实中标价，不是我们的报价）

苏州公共资源交易平台上的公开中标结果，每个价格点对应一个独立项目：

| 品类 | 真实中标价 |
|---|---|
| 普通溯源秤 | 1350 / 2145 / 2566 元/台 |
| 彩屏溯源秤 | 1400 元/台 |
| AI 称 | 2850 元/台 |
| AI 智慧溯源秤 | 3350 元/套 |
| 触屏 AI 收银一体秤 | 4425 元/台 |

另外两项容易被漏掉的开支：

- **摊位小屏 1100 元/台**（同一项目里 141 台）。但目标如果只是"让顾客看得见价格"，防水价签、抽拉式价格牌也能做到，**成本低一个量级**。
- **网络改造比秤还贵。** 中山一个智慧农贸项目里，WiFi 综合覆盖布线 88 万元 + 互联网专线 32.5 万元，两项合计占整个 **366.9 万元标的的 33%**。

**按 300 个摊位算一笔粗账**（这是我们的测算，不是报价）：

| 项目 | 300 摊合计 |
|---|---|
| 秤（非 AI 溯源秤档） | 40.5 万 – 77 万元 |
| 摊位小屏（可选） | 33 万元 |
| 秤 + 屏小计（不含网络） | 73.5 万 – 110 万元 |
| **省掉小屏、改用物理价签** | **约 40 万 – 80 万元** |

网络那一项**只举一个例子、不给区间**：不同市场的网络基础差异太大，而我们手上只有中山这一例，**必须实测**。

这笔账只回答一个问题：**这笔投入是十万级还是百万级。** 答案是**百万级**，而按上海宝山的口径，补贴理论上能覆盖约一半。所以路只有一条：**市场方出资 + 政策补贴 + 银行合作**，不能走"商户自费"。

## 五、我们从调研里读出的六条

1. **不要跟商户收钱。** 有督查先例，费率再低（2‰）也会被纠正，严重时商户直接用脚投票。
2. **设备不能让商户掏钱，而且要包修包检定。** 光"免费"不够，"免费 + 免维护"才行；维修不及时是设备落灰的第一原因。
3. **扫码页要先有数据再给人看。** 没有采集流程的展示字段，做出来就是"应付检查的贴纸"。
4. **验收要看"用没用"，不是"装没装"。** 否则会复制武汉那套结局。
5. **钱找银行和政府。** 银行要存款和贷款客户，政府要本地消费统计，两边都有真实的付费动机。
6. **屏幕可以用便宜的替代。** 目标只是"价格看得见"时，物理价签比电子屏便宜一个量级。

## 六、我们的核心主张，和它划出来的两个范围

一句话：

> **在不增加摊主操作负担的前提下，产生可核验的交易数据——数据可信度优先于功能数量。**

这句话决定了后面几乎所有取舍。举两个例子：

- 为什么**禁止打字**：摊主手上是湿的、还要招呼客人，现场不允许打字；
- 为什么**宁可不做某个功能**：只要它没有真实数据来源，做出来就是"应付检查的贴纸"。

**两个范围必须分开说，否则会互相误导：**

| | 内容 | 这一期 |
|---|---|---|
| 本期实现 | 单市场（数据面）、不依赖外网、数据存本地、前端适配手机宽度；并发按**演示级**设计（峰值不到 20） | **真做** |
| 方案论证 | 多市场的运营流程（跨市场权限、结算、报表）、**单市场约 300 个摊位**、早市高峰 | **只讲思路，不做实现** |

**演示规模是实测值，不是估计**：1 个市场 × **10 个摊位** × 每摊位 **25 个商品** = **250 条商品**；标准品类 **58 个**（蔬菜 20 / 水果 13 / 肉类 13 / 水产 12）；摊位别名 **351 条**。

也就是说：**这一期不是"支持 300 个摊位"，而是"数据模型和部署形态按 300 摊的目标设计，但只装一个市场、10 个摊位把它跑通"。** 把这句话说在前面，比事后解释"为什么演示数据里只有 10 个摊位"要好。

另外有两个部署形态，这一期都做：

| 形态 | 怎么跑 | 用来干什么 |
|---|---|---|
| **单机版** | 一个进程里同时有秤端页面、运营端、顾客页和全部账务 | 现场演示主路径 |
| **分离版** | 秤端（摊位现场终端）× N ↔ 中台（中心服务）× 1，走网络连接 | 对应"100 个商家 = 100 台秤 + 1 个中台"的目标形态 |

**两种形态是同一套能力的两种部署方式，不是"完整版"和"简化版"。** 单机版不会因为分离版做出来就废弃——现场无 WiFi 时它还是主路径。

## 七、关键假设：哪些有依据，哪些我们只能给方向

做方案最危险的不是"漏做了什么"，而是**把假设当成了已确认的需求**。所以我们把假设分成两类，分开摆。

### 有依据、可以直接用的

| 假设 | 依据 |
|---|---|
| 硬件由市场方出资，采购范围含维保与计量检定 | 绵阳（免费但无维护 ⟶ 积灰弃用）对照衡阳/杭州（免费 + 统一检定 + 免维护 ⟶ 存活） |
| 交易必须走秤（唯一物理锚点） | 温州模式的可执行抓手就是"买方必须用市场的秤 + 出口查验交易凭证"；没有锚点，流水就不可信 |
| 必须支持现金录入 | 南宁 POS 刷卡全部停用，摊主原话"还是用现金交易比较好"；只做电子支付会丢掉大部分交易，流水就不完整，佣金口径就失真 |
| 默认选非 AI 溯源秤档 + 物理价签 | 有真实中标价区间；我们的目标只是"价格可见 + 称重可追溯" |
| 收款通道费率 0.38%–0.6% | 微信支付对小微商户的公开结算规则；市场方抽佣是在这之上再加一道 |

> **这一条我们改过一次，值得说一下**：调研里这条结论原来的标题写的是"先有 19%–30% 被收款通道拿走"——**那个数字全文没有来源，而且和正文的 0.38%–0.6% 自相矛盾**，所以被删掉了，正文只留可查证的那一段。**在无数据处给一个精确数字，比不给数字更危险，因为它会被当成事实引用下去。**

### 没有依据、我们只给方向的

下面这些**没有公开数据**，所以我们在方案里只写方向、不写具体数值。**在没有数据的地方给一个精确阈值，等于把假设包装成事实。**

| 参数 | 为什么给不出数 |
|---|---|
| 设备年故障率 | 公开渠道查不到"设备每年坏多少、修一次多少钱" |
| 维修单价 | 同上，没有公开成交价 |
| 罚款金额 | 无公开数据 |
| 顾客扫码率基线 | 青岛那条报道自己承认"主动扫码评价的比例仍缺乏统计" |
| 信任的衰减 / 恢复速率 | 无公开数据 |
| 商户的退出阈值 | 无公开数据 |
| 单摊位日均笔数与峰值时段 | 属于行业常识，**未经调研验证**，只能当容量规划的假设 |
| 电子价签 / 可擦写标签单价、年维修成本、存量秤加装蓝牙的改造价 | 只有"有人在做"的定性，没有单价 |

我们的仿真里每条参数都标了"有来源"还是"假设"：**没有来源的参数只允许出现在方向性判断里**（谁高谁低、两个区间是否重叠），不允许单独支撑一个绝对结论。

> 后面每次引用仿真结论，都会带上用的规模和档位。这不是形式主义——**同一个机制在不同的规模和故障率下，结论可以完全相反**，第九节会有一个具体例子。

## 八、这一期做什么、不做什么

### 做的（主干 + 两个证明点）

商户/摊位建档 · 商品与价目表（含营业前设置和"复制昨天价"）· 模拟电子秤 · 计价 · 交易 · 模拟支付（成功/失败/超时/回调四种结果）· 交易与退货冲正 · 佣金引擎（口径可配、退货冲减、按日聚合）· 结算单 · 经营看板（商户端 + 市场方端）· 对账 · **断网离线交易 + 补传幂等** · **轻量摊位信用档案**。

其中两个是**证明点**：断网补传（证明同一单绝不重复计佣）、信用档案（证明扫码页上显示的每个字段都有真实来源）。

### 不做的（15 条，每条都写清楚理由）

| 不做 | 为什么 |
|---|---|
| 外送服务 | 不在这次要解决的问题里 |
| 顾客端历史价格折线图 | 同上 |
| 真实支付平台对接（支付仍是模拟） | 题目明确允许模拟；真实对接涉及牌照与合规，不是这一期的事 |
| 真实硬件采购、产线试制、硬件在环验收 | 这一期交付的是软件 Demo + 配套硬件设想，硬件实测放在选型确定之后 |
| 多市场的运营流程（跨市场权限 / 结算 / 报表） | 中台**保留了"市场"这一维度**，第二个市场不用改表结构就能装进来；但跨市场的运营流程这一期不做 |
| 完整权限体系（不做 SSO、不做权限矩阵、不做岗位分离） | 真实业务里"配佣金口径""对账""审结算单"可能分属运营和财务两个岗位，这一期合并成一个人 |
| AI 图像识别自动选品 | 交易中一律人工选品 |
| 电子价签、摊位屏、大屏等非秤类硬件 | 摊位小屏的成本前面算过，这一期用物理价签替代 |
| 发票开具与税务申报 | — |
| 会员、积分、优惠券等营销体系 | — |
| 商户贷款、授信、集采等金融与供应链业务 | 这些是"钱从哪来"里的论证内容（银行出钱、银行做授信），**不在交付范围** |
| 顾客端独立 App / 小程序 | 顾客只在扫码页完成支付和看信息，不装任何应用 |
| 演示游戏不做游戏性目标（无关卡、无积分、无胜负、无存档） | 演示游戏是为了让业务流程可看可点，不是为了玩 |
| 演示游戏不做商业级美术（不外包、不采购素材库） | 美术由脚本程序生成 |
| 演示游戏不新增任何服务端能力、不做多人联机 | 它只读、只调用既有接口 |

**把"不做"写这么细，是因为需求留白的地方如果不写清楚，就一定会被理解成"没做"。**

## 九、有哪些事我们还没做到

这一节是主动交底。写出来不是因为它们不重要，而是**希望你评估方案时，知道哪些是确定的、哪些还不确定**。

### 1. "向买方收费"这条路，我们没实现

温州模式是唯一活了二十多年的，但我们的佣金引擎**只实现了"向商户抽佣"这一种形态**。具体地说：**费率下限被限制在 1 个基点（万分之一）以上，写不进 0%**；而"收费对象"这个字段**只被记录、不参与计算**——配"向商户收"和配"向顾客收"，算出来的佣金金额**完全一样**。

这是我们规格上的一个空白，不是藏起来的问题。真要支持 0% 或买方付费，要改接口约定和计算逻辑，不在这一期。

### 2. 仿真不能证明我们的设计是对的

我们建了一套多智能体仿真，拿六条实地现象做了回测，**六条全部判定"不成立"**。

但这个"不成立"不是同一个意思，拆开是四类：

| 类别 | 几条 | 含义 |
|---|---|---|
| 不可评估（判据依赖没有依据的参数） | 3 | 机制上就判不了。这是我们拒绝给没有公开来源的参数下精确阈值的直接后果 |
| 欠功效（两组在中心档上逐位相同） | 3 | **该档位的分辨度不够，不是"没有效应"**——换参数档之后会翻转 |
| 真不通过 | 1 | 判据可判，值没达到 |
| 判据本身有问题 | 1 | 判据把"预算被外生压到 0.3 倍"和"预算随考核指标内生变化"混成了一件事，按原文永不可能成立，已经改了判据形式 |

**所以正确的话是**：仿真在既定的参数和可查证范围约束下，**无法独立判定这些失败案例**——多数是因为我们不肯给没有依据的参数编阈值。**这恰恰说明仿真没有被用来给结论背书。** 方案的依据始终是前面那 26 条调研结论。

### 3. "顾客信任能不能恢复"这个问题，我们是循环论证

我们跑出来一个结论：信任的可恢复性几乎完全由"采样机会的下限"决定——信任的不动点约 **0.72**，衰减半衰期 **9.6 期**（设计目标 8 期），**负面冲击留下来的持久度是正面维护的约 2.3 倍**。

**但这条结论的档位是"中心档 + 消费者决策层 + 120 期耦合"**，而且它是由**四个没有公开来源的参数**驱动的，所以只能表述成**关于参数的命题**，不能当成现实结论。**这一点我们没有解决。**

工程上唯一能落地的推论是：该动的是**保证总有样本**（强制抽检、公共计量公示），而不是去调信任的恢复速率——**恢复速率是观测量，不是可设计量。**

### 4. 仿真没有独立验证任何一条实地失败案例

- 抽佣 ⟶ 商户流失：**不可评估 + 欠功效**。在这套参数下，2% 的佣金**不足以翻转商户的决策**。
- 商户自费 ⟶ 弃用：**欠功效**。结论几乎完全由一个没有来源的参数决定。
- 温州模式 ⟶ 存活 20 余年：**纯不可评估**，五条判据全部没有依据。

顺带一个诚实的对照：仿真显示**在这套参数下 2% 的佣金不足以让商户改变行为**（走秤率和退出率两组逐位相同），这和现实中多个市场因抽佣而垮掉的记载**不一致**。我们保留这个不一致，不去调参数把它"调成一致"。

### 5. 有一套机制，只有在设备真的坏掉时才看得见

我们最有说服力的一条仿真结论是"只堵不养，比不堵还糟"：在堵死私下交易的前提下，如果市场方的考核口径是**装机量**而不是**使用率**，维护投入的考核收益就是 0，设备坏了不修，走秤率崩到 **0.059**，**明显低于"什么都不堵"的 0.220**，也远低于"堵死 + 考核使用率"的 0.590。

**这条结论的档位必须一起说**：**90 个营业日、8 个商户、每天 300 次到达、2 次重复、设备平均 10 天出一次故障**——这是**压力档**。

为什么必须强调档位：换回**基线档（设备平均 540 天出一次故障、60 个营业日）**重跑，第三臂的走秤率是 **1.0000**，和第一臂**完全相同**。查事件流才发现原因——**那 60 天里，一台设备都没坏过**。也就是说，这条机制在基线档下**根本没有载体**。

**"没跑出来"和"跑出来是好的"，是两件事。** 这一条后来成了我们引用仿真结论的规矩：**不带档位的数字不许用。**

### 6. 秤端的固件，从来没在真机上编译运行过

本机没有 ESP32 硬件，也没有 ESP-IDF。固件里只有**网络同步那一块**能在主机上编译并跑测试（我们用内存里的假端口驱动它，跑了 79 条断言）；**其余代码——WiFi、HTTP、文件系统、称重驱动、触摸屏界面、组合根——一行都没编译过，更没运行过**。构建用的组件版本号和分区表，也还没被 ESP-IDF 接受过一次。

### 7. 没有硬件在环

真实称重采样、触摸响应、WiFi 断连重连、掉电时序、Flash 磨损、屏幕在菜市场强光下能不能看清——**全都没测过**。

### 8. 秤的标定没做

固件里的传感器系数还是 `1/1` 的占位值，引脚和串口参数也还是占位。**接上真实传感器必须先标定**，标定完写进设备的持久存储里。

### 9. 分离版的传输层没加密

秤端和中台之间走的是**明文 HTTP**，靠设备令牌鉴权 + 受控局域网限制。我们为此申请了放宽并获批，**但批准的是"放宽"，不是"达标"**——上真机部署之前 TLS 必须补上，而且中台不能暴露到公网。

### 10. 设备注册有一个反直觉的行为

同一台设备重复做预注册时，系统会**换发一枚新令牌**。语义上这是"重复调用"的一个例外：一个以为重复调用没有副作用的运维脚本，拿旧令牌再调一次，会**静默作废已经烧进秤里的那枚令牌**，秤端下次激活就登不上。这一期靠运维纪律兜住（预注册只做一次），后面应该拆成"重复预注册"和"轮换令牌"两个明确的入口。

### 11. "市场"这个维度没有数据库级的外键

SQLite 不允许在已有表上加一个"带非空默认值的外键列"，所以市场归属的完整性只靠"默认市场那一行一定存在"加上应用层校验。手工 SQL、脚本、将来的迁移如果写错了市场号，会**静默产生孤儿行**——对账时表现为"数据凭空少了"。好在这类行**不会串账，只会消失**，因为所有读路径都带市场过滤。

### 12. 演示游戏会真实写库

每 45 秒大约 34 笔。**这和"演示层只读"的直觉不一样**，所以演示前如果希望看板从零开始，要先重置数据目录。

### 13. 看板上的佣金可能显示 0

这是**设计如此**，不是故障：如果数据库里没有当天生效的佣金口径，系统就不会计佣，也就没有金额可显示。被问到的时候，正确的回答是"库里没有生效的佣金口径，配一条就有了"，而不是临场编一个数。

### 14. 696 项测试里，有 3 项在这台机器上不适用

测试总数 **696 项**（接口契约 / 浏览器端到端 / 真并发性能 / 仿真四层）。本仓库开发环境（Linux / WSL）实测 **693 通过 / 3 项不适用**。

那 3 项断言写死了"数据目录必须在 C 盘"，而在不带盘符的 Linux 路径上这个断言必然不成立——所以它们是**环境断言，不是缺陷**。反证是同一台机器实测延迟 p50 6.0ms / p95 9.1ms，**比当初在 C 盘记录的 p50 19.6ms / p95 40.6ms 还好**。

**这 3 项我们没有在 Windows 演示机上单独复跑过**——这一点如实写在这里。

### 15. WebKit 内核没验

装了但起不来（缺 11 个系统库），代价和收益不成比例。已经验过两个内核（Blink 和 Gecko）。

## 十、还需要和你一起确认的事

这些不是我们能自己拍板的，需要运营方的实际信息或财务口径。

| 事项 | 需要你给什么 |
|---|---|
| **实地回访证据** | 我们**没有查到 2025–2026 年的实地回访**：反面证据集中在 2020–2022 年，最新只补到成都 2025 年空置那一个。**不能拿三四年前的情况直接给今天下结论。** 如果要反驳"情况已经改善"，需要重新检索一轮 |
| **硬件成本细项** | 电子价签 / 可擦写标签的实际成交价、年维修成本、存量秤加装蓝牙的改造价——都没有公开成交数据 |
| **商户与摊位底册怎么进来** | 真实业务里档案要从你现有的系统或纸质底册导入。**导入格式、字段范围、谁来负责**都需要确认。这一期用的是种子数据 |
| **离线暂存的加密存储** | 这一期没做，只作为已知风险声明 |
| **批发 / 团购的纸质凭证** | 绵阳案例里的抱怨就属于这一类。这一期零售场景不提供打印 |
| **使用频率与峰值时段** | 我们按主峰 06:00–09:00、次峰 17:00–19:00、单摊位日均 80–150 笔做的容量假设，**未经调研验证** |
| **财务证据链的保留期** | 交易流水、佣金明细、结算单、退货与改价留痕构成佣金结算的财务证据链。保留期要按《会计档案管理办法》和《税收征收管理法实施细则》**由你方财务确认适用口径**——我们不自行认定年限。数据模型已经按"可追溯、不可物理删除、支持归档"来设计，年限确认后只需加归档作业，不用改表结构 |
| **"市场口径的智能秤交易占比"这个指标** | 它的分母是**市场总交易笔数**，系统自己算不出来，只能来自人工盘点、抽样统计或外部系统。**这不是"实现口径待定"，而是这个指标本身超出了系统自有数据的范围。** 这一期我们改用了三个分子分母都来自系统自己的指标 |
