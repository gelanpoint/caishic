### 铁律 1 · 不可靠的东西不要留给环境（两条，同一类）

- **症状 A（`2026-10-02` 父代理现场验收）**：`cmd /c call D:\...\start.bat` → `exit=255`、`/healthz` 无响应，
  stderr 是 `'免安装打包，见' 不是内部或外部命令` / `'网、不使用' …` / `" was unexpected at this time.`，
  stdout 为空。**真因**：`cmd.exe` 按**控制台代码页**解析 `.bat` 的**字节**，中文被拆断成"命令"；
  出现在 `if ( )` 块内时，真正该显示的提示（"端口已被占用"）被解析错误顶掉。
  **处置**：`start.bat` 改为**纯 ASCII**（实测非 ASCII 字节 = 0），中文一律由 `scripts/launch.py` 打印。
  **注**：AI 在 8 个代码页下**未能复现**该症状 → 结论是"按机制移走整类风险"，不是"修好我复现到的那一行"。
- **症状 B（同一轮复测）**：父代理机器 `364 passed, 3 failed`（AI 本机 `367 passed`），
  报错形态 `assert '已启动' in '…\ufffd\ufffd…'`。**真因**：Python stdout 编码取自
  `PYTHONUTF8`/`PYTHONIOENCODING`/**系统 locale**；干净环境实测 `locale=cp936`、`stdout=gbk`
  ⇒ 子进程写 GBK 字节、捕获方按 UTF-8 解码 ⇒ 满屏 `\ufffd`。AI 本机"绿"只是因为**每条命令都带了
  `PYTHONIOENCODING=utf-8`**。
  **处置**：新增 `app/console.py::force_utf8_stdio()`（**被重定向时强制 UTF-8**、接真控制台时沿用控制台编码），
  `run.py` 与 `scripts/launch.py` 都自定编码；**测试捕获一律显式 `encoding="utf-8", errors="replace"`**。
- **铁律条文**：**输出编码不许依赖环境变量；测试捕获一律显式编码；验收基线 = 清掉
  `PYTHONUTF8`/`PYTHONIOENCODING` 后仍然绿**（由 `tests/e2e/test_demo_launcher.py` 两条回归盯着；
  灵敏度已实测：关掉修复必红 → 还原复绿）。
  > 顺带记一个坑：`cmd /c "set PYTHONUTF8= && python …"` 里 `&&` 前的**空格会被算进变量值**
  > （实测变成 `" "`）→ `Fatal Python error: preconfig_init_utf8_mode: invalid PYTHONUTF8 environment
  > variable value`，Python 直接起不来。正确写法**不带空格**：`set PYTHONUTF8=&& python …`。

### 铁律 2 · 交付前跑一次「新克隆验证」

- **症状（`2026-10-02`，并行仿真线发现）**：`.gitignore` 里的 `env/` **未锚定**，导致 `sim/env/`

- **铁律条文**：**交付前按 `.gitignore` 之外的方式做一次「新克隆验证」** ——
  在干净目录 `git clone` 本仓库（或 `git archive` 解包）后跑一遍启动与全量测试；
  **本地绿不等于交付绿**（与"靠环境变量的通过不算通过"是同一条道理的另一面）。
