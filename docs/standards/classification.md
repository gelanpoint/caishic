# 定级：三问、判定表、兜底规则、升降级

> **本文件是本项目「项目级别为什么是 P2」的唯一复核依据**（定级判据的唯一权威）。
> 本文件已就地改造为**自包含**：所有路径均为本仓库内路径，不依赖任何外部目录。

级别决定后面所有环节的深浅。**先定级，再做别的。**

## 一、分级三问

每题只选一个最贴近的答案，一次问完。

### 问题 1：失败代价 —— 做砸了会怎样？

| 选项 | 含义 |
| --- | --- |
| **1A** | 只影响自己或极小范围，坏了重跑一遍就行（个人脚本、一次性数据清洗、自用查询小工具） |
| **1B** | 影响一个团队的日常工作，坏了会被同事催，但可修复、可回退（团队内部管理系统、内部报表） |
| **1C** | 影响客户交付，或涉及资金、发票、合同、**个人敏感数据**、生产业务数据 |

### 问题 2：用户规模与并发 —— 多少人、以什么强度用？

| 选项 | 含义 |
| --- | --- |
| **2A** | 单用户或极少用户，无并发问题（个人工具、单机 RPA 流程） |
| **2B** | 团队级（数十人以内），低并发，使用模式可预期（部门内部系统、内部审批流） |
| **2C** | 外部用户或用户量不可控增长，存在并发与峰值压力（对客户开放的门户、对外 API、面向全员或公众的系统） |

### 问题 3：生命周期 —— 这个东西活多久？

| 选项 | 含义 |
| --- | --- |
| **3A** | 一次性，用完即弃或几乎不维护（迁移脚本、临时对数工具） |
| **3B** | 季度级迭代，有持续但不频繁的维护 |
| **3C** | 年度级长期维护，可能多人接手、需要移交（客户交付系统、公司级平台） |

## 三、兜底规则（优先级最高，压过判定表全部行）

> 1. 问题 1 选 **1C**（涉钱、涉敏感数据、涉客户交付）者，**无论另外两问选什么，一律定为 P2，不允许任何理由降级。**
> 2. 拿不准选 A 还是 B、B 还是 C 时，**就高不就低**。
> 3. 定级结论与三问答案必须写入本特性的 `specs/market-trade-flow/spec.md` 头部，
>    作为后续流程深度取舍的凭据。

### 本次定级必须显式核对的清单

> **这是问题 1 的判据，不是第四问。** 它的作用是决定问题 1 该记 `1B` 还是 `1C`。

- 敏感数据项**逐项**回答是/否：个人信息（姓名/联系方式/身份证/**银行卡**）、支付信息、财务数据、健康数据。
- **任何一项为「是」→ 问题 1 记 `1C`**（并因此触发兜底规则，一律 P2）。答不出来也按「是」处理。
- 检查是否存在合同 / SLA / 客户验收条款 —— 有则同样是 `1C`。

**三问与答案编号的对应关系不能错位**：问题 1 → `1x`，问题 2 → `2x`，问题 3 → `3x`。
判定表是按这个对应关系索引的；错位会查到错误的行。

## 四、常见错误（会导致定级偏低，务必避免）

- ❌ **发明不存在的豁免条款。** 本规则**没有**"内部数据不对外支付所以可以降级"这类例外。
  只要触及个人敏感数据（含银行卡号、身份证号），**一律 P2**，哪怕系统只在内部使用、只在展示层用到。
- ❌ **把级别当面子。** 把 P2 报成 P1 以赶工期，是在拆掉整条流程最重要的防线。
  反向也一样：把 P1 报成 P0 以省流程，是拿安全换时间。
- ❌ **拿"演示用途"套本流程。** 只用汇报演示、不会被真实使用的交付物，不适用本分级；
  演示品要求转正时，**必须回到分级重新走一遍**。
- ❌ **只答两问就下结论。** 三问必须全部有明确答案，不允许"大概""可能"。

## 五、升降级

### 升级信号 → 必须补做的动作

| 触发 | 变化 | 补做 |
| --- | --- | --- |
| P0 被团队他人使用 | P0 → P1 | 补全需求访谈、补 NFR 基线核对、AGENTS.md 升到标准版、PR 强制评审 |
| P0/P1 被外部用户使用或用户量显著增长 | → P1 或 P2 | 重答问题 2，补架构决策树复核与 ADR，评估迁移到生产部署路径 |
| 开始处理资金/发票/个人敏感数据，或转为客户交付 | 任意 → **P2** | **立即**按 P2 全面补做：宪法补安全红线全文、ADR 补齐、测试达严格档、上线走生产路径 |
| 一次性脚本需反复使用或进入调度 | 3A → 3B/3C | 补 spec 的可维护性 NFR、规范化任务清单、纳入版本管理与评审 |

### 降级

- **仅当三问答案客观变化时**才可降级（如系统下线转为归档工具），且降级只对**尚未执行**的环节生效；
  已完成的评审与测试记录保留。
- **问题 1 的答案永不降级**：涉过钱、涉过敏感数据、交付过客户的系统，历史安全要求不撤销。

### 升降级操作

1. 重答三问，记录新旧级别与理由。
2. 更新 `specs/market-trade-flow/spec.md` 头部的定级信息。
3. 按升级信号表生成补做清单。
4. 同步下游文档（变更流程见 `.specify/memory/constitution.md` §5 第 3 条：
   **先改规格、同步下游、再改代码**）。

## 六、三级流程深度对照（本项目启动流程覆盖的环节）

「精简」= 用精简子集，单份文档产出控制在半小时内。
「完整」= 标准之上加评审/确认/归档。

| 环节 / 产物 | P0 | P1 | P2 |
| --- | --- | --- | --- |
| 0 分级与定级记录 | 精简：三问答案记入文档即可 | 标准 | 完整 + 逐项核对敏感数据留痕 |
| 1 需求访谈 | 精简：只问必答 7 题 | 标准：全 20 题 | 完整：全 20 题 + 合规项逐项留痕 |
| 1 `spec.md` | 精简：概述 + REQ + AC（NFR 可只列关键两条） | 标准 | 完整 + 逐条确认留痕 |
| 2 架构决策树 | **跳过**：直接取默认值（单体 + 单容器） | 标准 | 完整 + 判据答案留痕 |
| 2 ADR | **跳过**（默认值无需留痕） | 标准：仅非默认决策落 ADR | 完整：全部关键决策落 ADR |
| 2 NFR 基线核对 | **跳过**：采用基线默认值 | 标准：偏离项写回 spec | 完整 + 逐项确认记录 |
| 3 `constitution.md` | **精简：技术栈底线 + 安全红线 + 禁止事项 3 节**（约 15 分钟） | 标准：完整 8 节 | 完整 + 安全红线逐条确认 |
| 3 记忆锚 `AGENTS.md` | 精简版，但仍须含文档路由表 | 标准：≤150 行 | 完整 + 多工具配置核对 |
| 评审动作 | 自审即可 | 新会话 AI 对立评审 | 新会话 AI 对立评审 + 冷却期后复核 |

> **评审一律按"开全新 AI 会话 + 只给文档"执行**，不要求另一个人参与（本项目的前提是单人开发）。
> 找不到第二个人不是违规，**不做评审才是**。
