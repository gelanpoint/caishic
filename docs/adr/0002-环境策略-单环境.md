## 1. 背景与约束

- 架构默认值清单规定：**多环境 —— P2 强制三环境，且 staging 与 prod 配置同构**。本项目级别为 `P2`，
  因此**默认答案要求三环境**；本期采用单环境属于**对默认值的偏离**，故必须写本 ADR。
- 本期的现实约束（数字与事实来源）：
  - 交付物是**比赛作品**，生命周期 `3B`，**无年度级移交承诺**（R1 Q0.3）；
  - **本期实现范围**为单机、**一条命令启动、不依赖外网**、数据存本地（R0.3 硬约束）；
  - **总用户 ≤10、峰值并发 <20**，无外部用户（R1 Q0.2 / R3 Q2.2）；
  - **无专职运维**（R1 Q0.2 的现实推论，且 `spec.md` §4 已就运维类基线申请放宽并获批）。

## 2. 候选方案对比

| 维度 | 方案 A：本期单环境（dev 与 demo 合一，用配置切换种子数据） | 方案 B：三环境（dev / staging / prod，配置同构）**（默认方案）** |
| --- | --- | --- |
| 满足需求程度 | 满足：本期唯一的运行对象就是**本地单机 Demo** | 满足，但**本期不存在可部署的 prod 对象** |
| 开发成本 | 低：一套配置 + 一个种子切换开关 | 高：需三套配置、同构校验、部署脚本 |
| 运维成本 | 低：无环境需运维 | 高：三套环境需维护与同步；**与"无专职运维"直接冲突** |
| 回退成本 | 低：单环境，回退即换回上一版代码与数据文件 | 中：需分别回滚三套环境 |
| 迁移成本 | 中：转生产时需补三环境与同构校验（已在 §5 列触发条件） | 低：届时无需补 |
| 团队熟悉度 | 高：无额外要求 | 中：需环境治理能力 |

> 「运维成本」与「回退成本」两行为必填项，均已填。

## 3. 决策与理由

**结论：本期采用方案 A（单环境），偏离默认值清单的「P2 强制三环境」。**

**理由（必须追溯到第 1 节的数字与事实）**：三环境的前提是"存在一个生产环境需要保护"——
而本期**唯一的运行对象是本机 Demo**（第 1 节），没有外部用户（总用户 ≤10）、没有生产流量（峰值并发 <20）、
也没有可部署的 prod 对象；同时项目**无专职运维**。在这种情况下，三环境**没有对应的物**，
只会增加维护面而没有收益，并且与"单机、一条命令启动、不依赖外网"三条硬约束冲突。

**这不是"忽略"默认值，而是显式偏离**：本偏离的决策与批准留痕**就是本文件**（状态 `已接受`；
决策人见文件头「决策人」栏，经父代理确认）。它与 `spec.md` §4 的放宽偏离（`docs/PROJECT-STATE.md` `Q-11`，
**记录范围仅 `NFR-001`～`NFR-011`**）**属同一次放宽评审**，但**不在 `Q-11` 的记录范围内** ——
引用 `Q-11` 不能覆盖本条，本 ADR 自身即本条偏离的唯一留痕。
且**不属于"三类不予放宽"的红线范围**（安全红线 / 数据完整性与可核验 / 可追溯证据链 —— 均与环境数无关）。

## 4. 后果

**正面**

- 交付与演示路径最短：一条命令启动即得到可用的演示环境。
- 无环境同步成本；无"staging 与 prod 配置漂移"这一整类故障。

**负面**

- 若赛后转为真实生产系统，需要补建 dev / staging / prod 三环境并做配置同构校验（迁移成本见 §5）。
- 单环境意味着**演示数据与开发数据混用**，需依赖种子脚本 + 重置脚本保证可复现
  （已在 `spec.md` `AC-013` 与 §5 边界中约定）。
- 没有 staging 作为"上线前演练场"，任何变更都直接作用于演示环境。

## 5. 重新评估触发条件

**触发条件（任一即必须补建三环境并重评本 ADR）**：

1. 项目**从"比赛交付物"转为"真实生产系统"** —— 判定标准：出现**外部用户**（非交付方/评委）使用，
   或与甲方签署任何形式的服务/验收承诺；
2. 出现**需要保护的生产数据**（真实商户交易数据入库），或需要向第三方开放访问；
3. 引入**多人协作发布**（≥2 名开发者各自独立发布）。

> 本期状态：三条均未触发。
