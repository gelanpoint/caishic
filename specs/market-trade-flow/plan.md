## 1. 技术上下文

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 语言与版本 | Python 3.11 及以上 | 宪法 §1；低于 3.11 不保证可用 |
| 后端框架 | Flask | 版本锁定于仓库根 `requirements.txt`（**由实现环节创建**）；选型见 ADR-0003 |
| 前端形态 | 纯静态前端（HTML + 原生 JS + CSS），由 Flask 托管静态文件 | 不使用服务端模板渲染、无构建工具、无 npm、无 CDN（ADR-0003；`AGENTS.md` §3 硬要求 4） |
| 数据存储 | SQLite，经 **Python 标准库 `sqlite3`** 访问（WAL 模式，短事务） | 叶子 a 的嵌入式库（ADR-0001）；驱动不引入第三方（ADR-0003） |
| 部署形态 | 单机原生进程 + 启动脚本（`start.bat` / `start.sh`） | 不用 Docker、不用容器编排（ADR-0003） |
| 关键依赖 | 仅 **Flask**（直接依赖；其余一律用 Python 标准库） | 宪法 §1 依赖白名单；前端零第三方依赖 |

> **技术栈已由 ADR-0003 锁定，本方案不重新选型**；任何变更须先改 ADR 与宪法 §1。

## 5. 数据流描述

字段细节一律引用 [data-model.md](./data-model.md)，端点与错误码一律引用 [contracts/](./contracts/)。

1. **启动**：`run.py` 检测端口占用 → 打开/创建 `data/` 下的 SQLite 文件并执行 `app/migrations/` 顺序建表 → `app/seed.py` 从 `app/seed_data/` 导入商户与摊位、品类字典与别名、商品与价目表（`REQ-025`）→ 启动 HTTP 服务 → 打印局域网 IP、操作端与顾客扫码页两个入口地址、数据文件路径（`AGENTS.md` §3 硬要求 1/2/5）。
2. **营业前准备**：摊主设置本摊位价目表，支持「复制上一营业日价格」并逐条调整（`REQ-003`）；摊主选取的是摊位别名时，系统按**标准品类**记账（`REQ-002`，别名映射由 `app/domain/catalog.py` 维护）。
3. **一笔称重交易（主链路）**：摊主在秤端以图标/快捷键选品（`REQ-004`，无文本输入）→ 系统读取模拟电子秤重量、按「单价 × 重量」计价（`REQ-005`），多商品在同一笔内累加（`REQ-006`）；重量 ≤0 或 >50 公斤拒绝计价并提示（`REQ-027`）。
4. **改价 / 抹零**：摊主改价或抹零时写入改价留痕（原价、改后价、改价时间、操作摊位）；单笔幅度 >50% 仅提示确认、不阻止（`REQ-007`）；改价计入「标价一致率」、抹零不计入（`REQ-008`）。
5. **确认收款**：摊主选择收款码或现金（`REQ-009`）。现金在同一次写入中于**同一张支付流水表**落一条 `支付方式 = 现金` 记录（`REQ-010`）；收款码经进程内 Mock 支付回调落库，记录成功/失败/超时之一（`REQ-011`）。支付成功后先落库、再展示交易凭证，**不提供打印**（`REQ-012`）。
6. **幂等与失败处置**：同一次回调重复送达时按支付单号幂等、不重复记账（`REQ-029`）；回调失败或超时时摊主可重试或改记现金，系统保证该笔**只有一条交易记录、只计一次佣金**（`REQ-026`）。
7. **退货冲正**：摊主发起退货 → 校验退货金额不大于原单（`REQ-028`）→ 冲正原交易，商户端与市场方端的日聚合金额与佣金同步减少；同一笔退货重复提交**只冲减一次**（`REQ-013`）。
8. **离线 → 补传**：断网时继续接受新交易并本地持久暂存，秤端有明确可视的离线/在线标识且状态切换可在界面显式触发、可复现（`REQ-014`）；暂存达到告警阈值时提示摊主联系运维并**继续接受新交易**（`REQ-016`）；暂存写入失败必须明确报错且不得标记为成功（`REQ-030`）。网络恢复后按客户端生成的幂等键自动补传去重（`REQ-015`），**补传成功后清除本地副本**（`NFR-013`）。
9. **佣金与结算**：按配置的佣金口径（收费对象、费率、品种档位）以**实收金额**计算佣金（`REQ-017`）→ 日终按日聚合，退货冲正后支持按需重算（`REQ-018`）→ 依据日聚合生成结算单（`REQ-019`）→ 对账使「订单总额 = 支付流水 = 分账明细」可核验（`REQ-020`）。
10. **看板与指标**：商户端与市场方端两个看板展示交易、佣金与经营数据（`REQ-021`）；导出**三个**使用率指标 —— 摊位使用率、现金交易占比、价目表维护率（`REQ-022`，**2026-09-30 修订版**；分子分母的口径与表来源见 [data-model.md](./data-model.md) §5.1）。
11. **顾客扫码页**：只展示有采集来源的字段，无采集流程的字段不展示（`REQ-023`）；顾客不登录，页面不采集可识别顾客身份的信息。
12. **横切**：秤端只允许访问本摊位数据（`REQ-032`）；多摊位并发写入时交易号唯一、互不覆盖（`REQ-031`）；改价留痕、退货冲正、幂等命中记录写入只增不改的审计表（`NFR-009`）。

## 6. 外部集成点

| 集成对象 | 协议/方式 | 用途 | 失败降级策略 |
| --- | --- | --- | --- |
| 模拟电子秤（Mock） | 进程内模拟器，经内部接口读取 | 提供重量读数（`REQ-005`）；可注入故障 | 读数非法（≤0 或 >50 公斤）时按 `REQ-027` 拒绝计价并提示，**不静默给 0 值** |
| Mock 支付平台 | 进程内回调入口（无真实网络调用、无真实凭据） | 返回支付成功 / 失败 / 超时三种结果（`REQ-011`） | 失败或超时：交易保持待支付，摊主可重试或改记现金；系统仍保证**只有一条交易记录与一次佣金**（`REQ-026`） |
| 外部网络 / 第三方 API / CDN | **无** | — | 本期**零外部依赖**（`REQ-025`）；前端不引用任何 CDN，静态资源全部本地；断网由离线链路承接（`REQ-014`），并保证「同机双窗口分别扮演秤端与顾客端」可完成全流程演示（`AGENTS.md` §3 硬要求 3） |
| 真实硬件与真实支付 | **不集成** | — | 属 Out-of-Scope 第 3 条；如后续接入须先改 spec 与 ADR |
