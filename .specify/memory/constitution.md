## §1 技术栈底线

**允许的技术栈**（超出此表须先写 ADR 并评审）：

| 类别 | 选定 | 版本约束 |
| --- | --- | --- |
| 语言 | Python | 3.11 及以上 |
| 框架 | Flask（HTTP 路由、模板渲染、会话） | 版本锁定于实现环节产出的仓库根依赖清单 `requirements.txt`（**该文件由实现环节创建，本阶段尚未存在**） |
| 存储 | SQLite，经 **Python 标准库 `sqlite3`** 访问 | 随 Python 3.11+ 提供，不引入第三方驱动 |
| 前端 | 纯静态 HTML + 原生 JavaScript + CSS | **无构建工具、无前端包管理、无 CDN**，全部静态资源为仓库内本地文件 |
| 运行形态 | 原生进程 + 启动脚本（`start.bat` / `start.sh`） | **不使用 Docker、不使用容器编排** |
| 依赖来源 | PyPI 官方源，仅限依赖白名单内 | 白名单见下 |

**依赖白名单（约束范围：运行期依赖）**：`Flask`（及其在 `requirements.txt` 中锁定的传递依赖）/ **Python 标准库（一律允许）**。> **本白名单约束的是"运行期依赖"** —— 即 `run.py` 与 `app/**` 在交付与演示时所依赖的东西，
> 也是演示机上必须安装的东西。**开发与测试期使用的工具不属本白名单范围**，另见下方「开发期工具」小节。
> （本节表述于 `2026-09-30` 由 `v1.1` 澄清，原因与新 ADR：`docs/adr/0004-依赖范围界定-运行期与开发期.md`）
> **前端零第三方依赖** —— 不得引入任何 npm 包、JS 框架或外部样式库（**含开发期**：前端无构建、无包管理）。
> 新增**运行期**后端依赖必须：来自白名单内，或先补 ADR 说明理由。

**秤端技术栈例外（`v1.2`，`2026-10-06` 批准；依据 `docs/adr/0006-秤端嵌入式技术栈.md`）**：

| 类别 | 选定 | **适用边界（硬）** |
| --- | --- | --- |
| 语言 | **C（ESP-IDF）** | **仅限 `scale-fw/**`**（摊位现场的秤端嵌入式固件） |
| 构建 | ESP-IDF 工具链 | **仅限 `scale-fw/**`**；**中台侧不得依赖它** |
| 主机侧验证 | `zig cc -target x86_64-linux-musl` | 用于 `scale-fw/core/**` 的**纯 C 核心**在无硬件条件下的单元测试 |

本条例外**只放开秤端固件**，边界如下（任一违反即越权）：

1. **不放开中台侧**：`run.py` 与 `app/**` **仍只允许** Python 3.11+ 与本节白名单依赖，一字不改；
2. **秤端固件不得成为中台的运行期依赖**：中台不得 `import` / 执行 / 链接固件产物；
3. **`scale-fw/core/**` 不得 `#include` 任何 ESP-IDF 头文件** —— 这是"无硬件也能验证核心逻辑"的前提（`Q-21`），破了它等于放弃验证；
4. 秤端**不引入**白名单外的第三方 C 库；确需引入须另立 ADR（依赖纪律参照本节与 `docs/adr/0004-依赖范围界定-运行期与开发期.md`）；
5. 秤端固件**只依赖** `docs/standards/quality-gates.md` 定义的阈值，**不复制**任何数值。

**开发期工具（仅限开发与测试期）**：

| 项 | 约定 |
| --- | --- |
| 允许的工具 | `pytest`、`coverage`（**仅开发与测试期使用**） |
| 清单位置 | 独立的 `requirements-dev.txt`（自有开发机使用） |
| **硬边界** | **不得出现在 `requirements.txt`**；**不得被 `run.py` 或 `app/**` 引用（含 `import`）**；**不安装到演示机** |
| 机械检查 | 用 `ast` 扫描 `run.py` 与 `app/**` 的 `import`，确认不含任何开发期依赖；**该检查必须带灵敏度验证**（故意 `import pytest` 时必须变红） |
| 端到端实证 | 在**只安装 `requirements.txt`** 的干净环境中，`python run.py` 必须能启动 |
| 边界说明 | 开发期工具自身的漏洞**不在**运行期漏洞响应时限的适用范围内（见 `docs/standards/quality-gates.md` §1.1） |

> 新增开发期工具**不需要**修订本节，但必须：留在 `requirements-dev.txt`、不违反上面的硬边界、
> 并把清单变化写进对应提交说明。**判定不清某物属于哪一期时，按"运行期"从严处理。**

> 选型依据：`docs/PROJECT-STATE.md` `Q-13`（2026-09-30 闭环）；

> 叶子分支判定依据：`docs/adr/0001-单体与嵌入式数据库.md` 与 `docs/standards/architecture.md`；

## §2 安全红线

> **本节任何级别项目都不可豁免。** 本项目为 `P2`，全部条目一律适用，不做任何缩水。

1. **密钥绝不入库** —— 任何环境、任何分支、任何历史提交。密钥一律用占位符或环境变量；
   全历史扫描（如 gitleaks）必须零命中。
2. **AI 不接触真实密钥** —— 生成配置时只产出占位符。
3. **身份证号与银行卡号一律不得出现** —— 在任何接口的**请求体、响应体与持久化记录**中均不得出现
   这两类字段；收款标识必须**脱敏存储**。（对应 `specs/market-trade-flow/spec.md` `REQ-024` / `NFR-012`）
4. **敏感字段必须脱敏** —— 展示与日志中的个人敏感信息须脱敏；
   具体脱敏口径见 `docs/standards/nfr-baseline.md` 对应级别列，**本文件不复述口径**。
5. **不记录敏感数据到日志** —— 日志不得包含身份证号、银行卡号、密码、令牌。
6. **离线暂存交易数据的处置** —— 离线暂存交易数据属敏感数据处理范围，
   **补传成功后必须清除本地副本**（对应 `NFR-013`）；
   暂存数据的**加密存储**是已知演进项，不在本期实现（见 `docs/PROJECT-STATE.md` `Q-7`）。
7. **绝不静默丢弃任何一笔交易** —— 本地暂存达到告警阈值时**只告警、仍继续接受新交易**；
   暂存写入失败必须向操作者明确报错，且不得把该笔标记为已成功记账。
   （对应 `REQ-016` / `REQ-030` / `NFR-014`）
8. **最小权限** —— 服务账号与数据库账号只授予必需权限；秤端只允许访问本摊位数据（`REQ-032`）。

## §3 质量门禁引用条款

**本文件不定义任何质量阈值数字。**

- 质量阈值（覆盖率、圈复杂度、文件行数、PR 规模、测试金字塔比例）：
  见 `docs/standards/quality-gates.md`。
- 非功能基线（响应时间、可用性、备份保留期、脱敏口径等）：
  见 `docs/standards/nfr-baseline.md`。
- 本项目对基线的偏离项与其批准记录：
  见 `specs/market-trade-flow/spec.md` 的非功能需求章节（含 §4.1）。

任何文档、代码注释或 CI 配置中出现阈值时，**只允许引用，不允许复述数值**。

## §4 架构约束

- **默认单体**（决策树叶子 a）。采用非单体架构必须有状态为「已接受」的 ADR。
- 架构决策一律记录在 `docs/adr/` 下、命名为 `NNNN-决策标题.md`，全项目只用这一套命名。
  全部 ADR 及其状态登记在根 `AGENTS.md` 的文档索引里（**唯一登记处**，不另设独立的 ADR 索引文件）。
- 禁止绕过 `docs/adr/` 中已接受的决策另起一套实现。
- **运行形态约束**：本期为单机原生进程；禁止引入 Docker、外部数据库服务、消息队列、
  缓存中间件与任何需要访问外网的运行时依赖（默认值清单的采纳结论见 ADR-0001 §3）。
- **资金链路的证据链不可削弱**：改价留痕、退货冲正、幂等命中记录**只增不改**；
  对账等式（订单总额 = 支付流水 = 分账明细）必须可被第三方核验。

## §5 禁止事项清单

1. 禁止把密钥、连接串、内部地址写入版本库或 AI 上下文。
2. 禁止在未评审的情况下合入 AI 生成的大段代码（规模阈值见 §3 指向的文件）。
3. 禁止跳过规格直接改代码 —— 规格与现实矛盾时按「先改规格、同步下游、再改代码」处理。
4. 禁止一次性生成整个系统而不做任务拆解与评审。
5. 禁止在文档里复制其他文件的阈值数值或清单条目。
6. 禁止提交占位符（未填实的尖括号字段、全角方括号占位符）—— 填不出就删掉那一行。
7. 禁止前端引用任何 CDN 或外部资源 —— 不依赖外网是硬约束，静态资源一律为仓库内本地文件。
8. 禁止静默丢弃交易、禁止把未成功落库的交易标记为成功（见 §2 第 7 条）。
9. 禁止 AI 自行修改本宪法 —— 修订必须走 §6 的人工评审程序。
